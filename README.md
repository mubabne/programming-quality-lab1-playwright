# Лаборатори 1 — Playwright

Ч. Мөнхбаяр — B242270045

**Хийсэн ажил**

SauceDemo сайт дээр зөв нэвтрэх, буруу нууц үгээр нэвтрэх, нэвтэрсний дараа бараа сагсанд нэмэх гэсэн 3 тест бичсэн. Буруу нууц үгийн тест нь нэвтрэх ёсгүй үед алдааны мэдэгдэл гарч байгааг шалгадаг учраас pass болно. Амжилттай нэвтэрсэн хоёр тестийн төгсгөлд Logout хийнэ. Бүх тест tests/mytest.spec.ts файлд байгаа бөгөөд Chromium, Firefox, WebKit дээр нийт 9 тест амжилттай ажилласан.

**Codegen-оос ажигласан зүйл**

Codegen-оор нэвтрэх, Sauce Labs Backpack-ийг сагсанд нэмэх, гарах үйлдлийг бичүүлсэн. Үүссэн код ажиллаж байсан ч гараар бичсэн тестээс уншихад арай төвөгтэй санагдсан. Codegen нь username, password, Login болон Logout-д data-test атрибуттай locator сонгосон бол үндсэн тестэд getByPlaceholder, getByRole ашигласан. Мөн талбар дээр click хийгээд дараа нь fill хийх хоёр үйлдэл бичигдсэн; үндсэн тестэд шууд fill хийсэн. Recording нь Backpack барааг нэрлэсэн атрибутаар сонгосон, харин үндсэн тест эхний Add to cart товчийг сонгодог. Recording-д үр дүн шалгах assertion байхгүй тул сагсны тоо 1 болсон эсэх, Remove товч харагдах эсэхийг үндсэн тестэд тусад нь шалгасан. Recording-ийг гурван browser дээр тусад нь ажиллуулахад 3 pass болсон.

**XPath яагаад ашиглаагүй вэ?**

Login товчийг getByRole-оор, хэрэглэгчийн нэрийн талбарыг getByPlaceholder-оор олоход яг ямар элемент сонгож байгааг ойлгоход амар байсан. DOM-ийн олон түвшин заасан XPath нь хуудасны бүтэц өөрчлөгдөхөд эвдэрч болох тул энэ ажилд хэрэг болоогүй. Сагсны тоог шалгахад .shopping_cart_badge гэсэн богино CSS locator ашигласан.

**Trace дээрх алдаа**

Products гэсэн зөв текстийг Products - intentional failure болгож түр өөрчлөөд тестийг санаатай унагасан. Login амжилттай болсон ч хуудаст байхгүй текстийг 5 секунд хүлээгээд assertion алдаа өгсөн. Зөв текстийг буцааж тавьсны дараа бүх 9 тест дахин pass болсон. Алдаатай assertion эцсийн кодонд үлдээгүй.

**Playwright ба Selenium**

Playwright болон Selenium хоёулаа browser дээр үйлдэл автоматжуулж веб сайт шалгахад ашиглагддаг. Playwright Test-д тест ажиллуулах, assertion, HTML report, trace зэрэг нь нэг багцад байгаа нь энэ лабораторид тохиромжтой байсан. Selenium WebDriver ашиглах үед тестийн framework болон тайлангийн хэрэгслээ тусад нь сонгож болдог. Playwright нь үйлдэл хийхээс өмнө элементийн бэлэн байдлыг автоматаар хүлээдэг. Selenium-д ч implicit болон explicit wait байдаг. Энэ ажилд тогтмол sleep ашиглахгүйгээр URL, текст, товчны төлөвийг assertion-аар шалгасан. Нэг config-оор Chromium, Firefox, WebKit дээр ижил тест ажиллуулж болсон. Аль хэрэгслийг ашиглах нь төслийн шаардлага болон багийн ашигладаг орчноос хамаарна.

**AI ашигласан тухай**

AI-аас logout нэмэх, тест ажиллуулах, Git болон trace-ийн алхмууд, README-ийн тайлбарт тусламж авсан. Codegen-ий кодыг уншихад арай төвөгтэй санагдсан ажиглалтаа бичиж, тайлбарыг нь цэгцлүүлэхэд мөн ашигласан. AI-ийн санал болгосон өөрчлөлтийг бодит browser дээр ажиллуулж шалгасан. Зөвхөн код ажиллах нь хангалтгүй, тестийн үр дүнг assertion-аар шалгах болон нотолгоогоо хадгалах хэрэгтэй гэдгийг энэ ажлын үр дүн харуулсан.

Эх сурвалж: [Playwright Locators](https://playwright.dev/docs/locators), [Codegen](https://playwright.dev/docs/codegen), [Selenium Waits](https://www.selenium.dev/documentation/webdriver/waits/).
